> Перевод файла [SPEC.md](../../SPEC.md), сгенерированный из того же источника, что и страница [www.8pwd.com/ru/open-format](https://www.8pwd.com/ru/open-format). При расхождениях преимущественную силу имеет английская версия.

Нет сервера — значит, файл это всё. Поэтому формат файла публичный: он полностью задокументирован на этой странице, передан в общественное достояние и сопровождается примерами файлов и верификатором, который можно запустить без 8PWD. Если бы мы завтра исчезли, ваши пароли так и остались бы читаемым файлом.

## Что здесь значит «открытый»

- **Задокументирован**: каждый элемент и атрибут, который записывает приложение, перечислен на этой странице вместе с правилами, которым должна следовать читающая программа.
- **Общественное достояние**: спецификация опубликована под **CC0 1.0** — кто угодно может писать программы для чтения, записи или конвертации, не спрашивая нас, не упоминая нас и ничего нам не платя.
- **Проверяемый**: [verify_8pwd.py](../../tools/verify_8pwd.py) (CC0) разбирает, подсчитывает и расшифровывает резервную копию без зависимостей, кроме Python 3.
- **Стабильный**: номер версии только растёт; новые разделы только добавляются в конец; читающая программа игнорирует то, чего не знает. Изменения формата перечислены на странице [Что нового](https://www.8pwd.com/ru/changelog).
- **Зеркалирован**: эта страница, оба примера файлов и верификатор продублированы на [github.com/MNV-LIMITED/8pwd-format](https://github.com/MNV-LIMITED/8pwd-format) (на английском), где каждое изменение формата сохраняется в публичной истории с датой.

Само приложение не имеет открытого исходного кода; открыт формат. Для ваших данных важно именно это обещание.

## Незашифрованная резервная копия: один XML-файл в UTF-8

Экспортируйте без пароля — и вы получите файл `.8pwd`, который представляет собой обычный XML. Корневой элемент — `<vault>` с атрибутами `app` (название продукта), `version` (сейчас **8**), `exportedAt` (ISO 8601, UTC), `nodes` и `formattedBlocks` (счётчики). Внутри, в таком порядке:

- `<tree>` — папки и аккаунты. `<folder uuid name>` вкладываются друг в друга без ограничений. `<account uuid name favorite icon category created updated>` содержит `<fields>`, и каждый `<field name kind hidden>value</field>` — одна строка записи. `created` и `updated` *(5.0)* необязательны: время создания записи и её последнего изменения в секундах Unix.
- **Смысл** поля задаёт его `kind`: `username`, `password`, `url`, `email`, `phone`, `note` или `text` (произвольное пользовательское поле). `name` — лишь подпись, которую видит пользователь; она локализована («Password», «密碼», «Passwort») и не должна использоваться, чтобы определять тип поля. `hidden="true"` помечает поле, которое приложение по умолчанию скрывает.
- `<formattedBlocks>` — многоразовые текстовые блоки (в приложении — «Пароли по шаблону»): `<formattedBlock uuid name recordSeparator>` с `<template>` и `<accountRefs><ref uuid/></accountRefs>`.
- `<totps>` — секреты двухфакторной аутентификации в виде стандартных URI `<totp uuid note linkedAccount>otpauth://…</totp>`; `linkedAccount` — uuid первого аккаунта, к которому они относятся (оставлен ради старых читающих программ — полный набор связей «многие ко многим» находится в `<links>`, см. ниже). Такой URI импортирует любой аутентификатор.
- `<recoveryCodes>` *(4.0)* — одноразовые резервные коды, которые сайт выдаёт при настройке двухфакторной аутентификации: по одному элементу `<codes totp="uuid">free text, newlines kept</codes>` на каждую запись с кодами. Раздел вынесен за пределы `<totp>`, чтобы URI оставался чистым URI.
- `<links>` *(4.0)* — `<link account="uuid" kind="totp|card|identity" target="uuid"/>`: какие коды двухфакторной аутентификации, карты и записи личных данных относятся к каким аккаунтам, по схеме «многие ко многим». Оба конца — uuid, которые встречаются в другом месте того же файла; программа, которой нужны только пароли, может пропустить этот раздел.
- Внутри `<account>` *(4.0)*: необязательные дочерние элементы `<alias>other sign-in name</alias>` перед `<fields>` — другие имена пользователя или адреса эл. почты этого аккаунта. Поиск и автозаполнение в приложении их учитывают; читающая программа может считать их дополнительными именами пользователя для того же пароля.
- `<wifi>` — сети Wi‑Fi: `<network uuid ssid security password hidden note/>`.
- `<cards>` — `<card uuid number name cardholder expMonth expYear cvv pin issuer note owner …/>` плюс атрибуты платёжного адреса с префиксом `b` (`bName`, `bStreet1`, `bCity`…).
- `<identities>` — `<identity uuid title firstName lastName username company jobTitle birthday idNumber passportNumber licenseNumber note owner created updated>` с дочерними элементами `<email label>`, `<phone label>` и `<address label aStreet1 aCity aRegion aPostal aCountry/>`.
- `<passkeys>` — `<passkey uuid rpId rpName userName userDisplayName userHandle credentialId privateKey signCount note owner created lastUsed/>`; двоичные значения записаны в Base64. Ключи доступа записываются **только** в зашифрованные резервные копии.
- Служебные разделы, которые приложение использует для себя: `<preferences>` (ярлыки вкладки «Главная», а начиная с 4.0 — сетка «Я › Моё избранное» в виде `<quickAccess>` / `<quickAccessHidden>`), `<usage>`, `<siteNotes>`, `<checkups>`. Программа, которой нужны только пароли, может их пропустить.

Правила для читающих программ: неизвестные элементы и атрибуты игнорируются; отсутствующие необязательные разделы означают «ничего нет»; значения `uuid` стабильны от экспорта к экспорту, поэтому один и тот же аккаунт сохраняет один и тот же id; даты в `created` / `updated` / `at` — секунды Unix.

Слияние двух копий *(5.0)*: если файл содержит аккаунт с `uuid`, который уже есть в приложении, **Умное слияние** оставляет копию с более поздним временем `updated` и помещает заменённый пароль в историю этого аккаунта; для аккаунта без `updated` (экспортированного до 5.0) сохраняется версия, которая уже есть на устройстве. Слияние никогда ничего не удаляет. Другие читающие программы могут следовать тому же правилу.

## Зашифрованная резервная копия: небольшой конверт вокруг того же XML

Включите **Зашифровать эту копию** (или добавьте ключи доступа) — и тот же XML запечатывается следующим образом, все числа в big-endian:

1. 8 байт: сигнатура ASCII `8PWDENC1`.
2. 4 байта: число итераций PBKDF2 как беззнаковое 32-битное целое — **600 000** при экспорте из приложения.
3. 16 байт: случайная соль.
4. 12 байт: nonce AES-256-GCM, за ним шифротекст и 16-байтовый тег GCM (обычная раскладка *nonce ‖ ciphertext ‖ tag*).

Ключ — это **PBKDF2-HMAC-SHA256** от пароля резервной копии в UTF-8 с этой солью и этим числом итераций, длиной 32 байта. Без ассоциированных данных. Открытый текст — описанная выше незашифрованная копия, байт в байт. Общие записи (`.8pwdshare`) и передача хранилища по AirDrop используют тот же конверт с одноразовым 6-значным кодом в качестве пароля.

Никакого проприетарного контейнера, депонирования ключей и секретов: зная пароль, файл открывают две строки кода из стандартной библиотеки.

## Примеры файлов

Оба примера содержат одно и то же выдуманное хранилище в формате 8: две папки, три аккаунта (у одного есть псевдоним, у каждого — время `created` / `updated`), один код двухфакторной аутентификации с кодами восстановления, одну сеть Wi‑Fi, одну карту и одну запись личных данных, а также раздел `<links>`, который связывает код и карту с их аккаунтами. **Все значения в них вымышлены**; ничто не принадлежит реальному человеку или сайту.

- [sample-plain.8pwd](../../samples/sample-plain.8pwd) — незашифрованный XML, 3 КБ. Откройте его в любом текстовом редакторе.
- [sample-encrypted.8pwd](../../samples/sample-encrypted.8pwd) — то же хранилище, запечатанное паролем `example`.

Оба импортируются в 8PWD, как любая другая резервная копия (**Я › Импорт › Файл резервной копии (.8pwd)**), так что вы можете точно увидеть, как содержимое файла соотносится с приложением.

## Проверить, пересчитать или расшифровать файл без приложения

`verify_8pwd.py` — один файл на Python 3, переданный в общественное достояние (CC0); для проверки зависимостей нет, для расшифровки нужен необязательный пакет `cryptography`.

1. `python3 verify_8pwd.py sample-plain.8pwd` — сообщает, зашифрован файл или нет, версию формата, дату экспорта, сколько в нём аккаунтов, папок, кодов, сетей, карт, записей личных данных и ключей доступа (а начиная с 4.0 — ещё псевдонимов, записей с кодами восстановления и связей), а также его SHA-256.
2. `python3 verify_8pwd.py sample-encrypted.8pwd --password example` — расшифровывает в памяти и выводит те же счётчики.
3. `python3 verify_8pwd.py Backup.8pwd --json` — машиночитаемый вывод для ваших собственных скриптов.

Скрипт никогда не пишет в файл и не обращается к сети. Сначала прочитайте его: он намеренно короткий.

## Другие способы выгрузить данные

- **CSV**: **Я › Экспорт › Экспортировать универсальный CSV** записывает общий набор столбцов (название, URL, имя пользователя, пароль, заметка), который импортируют «Пароли Apple», 1Password, Bitwarden и браузеры. Экспорт работает на любом тарифе, с Pro и без.
- **Коды двухфакторной аутентификации**: каждый `<totp>` — стандартный URI `otpauth://`; приложение также показывает их как QR-коды, по одному, для переноса в другой аутентификатор.
- **Бумага**: напечатанная книга паролей и аварийный набор — запасной офлайн-вариант для близких, которые останутся после вас.
